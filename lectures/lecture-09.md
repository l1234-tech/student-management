# Лекция 9. Компонентный frontend и современные фреймворки

*Текстовый конспект по презентации «Лекция №9» из предоставленного архива.*

## Императивный и декларативный подходы

Императивный подход требует вручную искать, создавать и удалять DOM-элементы, обрабатывать события, управлять состоянием и изолировать слои. Декларативный подход описывает, каким должен быть интерфейс при заданных props и state; фреймворк сам обновляет DOM при изменении данных.

## Компоненты, props, callback props и slots

Компонент — независимый переиспользуемый блок интерфейса. У него должен быть понятный контракт: какие данные он принимает, какие события генерирует, что отображает и какое состояние хранит.

**Props** — входные данные, передаваемые от родителя к дочернему компоненту сверху вниз. Дочерний компонент не должен напрямую изменять props. Callback props позволяют передать функцию для сообщения о событии родителю. Во Vue для событий обычно применяются emits.

**Props drilling** — ситуация, когда данные проходят через множество промежуточных компонентов, которым сами данные не нужны. При чрезмерном усложнении используют глобальное состояние или контекст.

**Slots** — точки расширения шаблона, куда родитель передаёт разметку или другие компоненты. Они позволяют использовать дочерний компонент как гибкий каркас.

## Реактивность и dependency tracking

Реактивность автоматически обновляет интерфейс при изменении данных. Dependency tracking отслеживает, какие вычисления и участки шаблона зависят от конкретных реактивных источников. Реактивные зависимости обычно ограничены жизненным циклом компонента и очищаются при его уничтожении.

В Vue используются `ref`, `reactive`, `computed` и `watch`. В React — hooks и Virtual DOM; в Angular — signals и change detection; в Svelte — компилятор и runes. RxJS предоставляет отдельную модель потоков данных.

Computed properties предназначены для производных значений и пересчитываются при изменении зависимостей. Watcher/effect выполняет побочный эффект при изменении отслеживаемых источников; побочные эффекты не следует использовать вместо обычных вычислений.

## Virtual DOM и reconciliation

Virtual DOM — объектное описание интерфейса. Reconciliation — процесс сравнения предыдущего и нового дерева, после которого фреймворк применяет изменения к DOM. В React на сопоставление влияют, в частности, тип элемента и key.

## Особенности фреймворков из презентации

- **Angular:** TypeScript, компонентная архитектура, DI, сервисы, CLI, signals.
- **React:** JSX, компоненты, props, hooks, Virtual DOM и reconciliation.
- **Vue:** однофайловые компоненты, Composition API, директивы, lifecycle hooks, composables, Vue Router и Pinia.
- **Svelte:** компиляция компонентов, встроенная реактивность, runes, stores и SvelteKit.

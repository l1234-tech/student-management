# 32. Синхронная и асинхронная валидация формы в SPA.

> Развёрнутый ответ из прежнего комплекта сохранён. Формулировка сверена с оригинальным PDF. Источники: лекции №2–11 и REST.pdf ([каталог](../../../../lectures/README.md)); дополнительные пояснения к API отмечены в ответе.

Синхронная проверка не ждёт внешнего ответа: обязательность, длина, формат, диапазон, совпадение полей. Асинхронная проверка обращается к серверу или внешнему источнику: например, доступен ли email или существует ли код группы. Синхронную проверку можно показать при вводе или blur; асинхронную следует ограничивать debounce и отменять/игнорировать устаревшие ответы.

Ошибку необходимо привязать к полю, сообщить её доступным образом и не полагаться только на цвет. Кнопку отправки можно блокировать при явно некорректных данных, но сервер должен повторно валидировать всё критичное: клиент легко обойти. Состояние асинхронной проверки должно различать `idle`, `checking`, `valid` и `error`.

**Опора на лекцию:** формы и проверка данных в клиентском приложении. **Дополнение:** конкретные правила предметной области определяет API.

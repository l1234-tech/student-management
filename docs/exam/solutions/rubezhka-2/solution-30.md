# 30. Optimistic UI: что происходит при оптимистичном обновлении и откате?

> Развёрнутый ответ из прежнего комплекта сохранён. Формулировка сверена с оригинальным PDF. Источники: лекции №2–11 и REST.pdf ([каталог](../../../../lectures/README.md)); дополнительные пояснения к API отмечены в ответе.

Optimistic UI сначала показывает ожидаемый результат, не дожидаясь сервера. Например, после отправки новой группы строка сразу отображается с новым значением, а запрос выполняется в фоне. Успех закрепляет серверный результат; ошибка требует откатить прежние данные и показать сообщение.

Для корректного отката сохраните предыдущую версию записи или patch-операцию, а запрос сопоставьте с конкретной сущностью. Нужно учитывать параллельные обновления: простой возврат всего старого списка может стереть более новое изменение. Оптимистичный подход лучше подходит быстрым, часто успешным и обратимым действиям. Для платежа или необратимого действия преждевременное подтверждение может вводить пользователя в заблуждение.

**Опора на лекцию:** состояние UI и обмен с REST API. **Дополнение:** механизм отката зависит от store/data-fetching библиотеки.

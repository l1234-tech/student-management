# 06. Dependency Injection во frontend. На примере Angular или аналогичного способа передачи сервисов.

> Развёрнутый ответ из прежнего комплекта сохранён. Формулировка сверена с оригинальным PDF. Источники: лекции №2–11 и REST.pdf ([каталог](../../../../lectures/README.md)); дополнительные пояснения к API отмечены в ответе.

Dependency Injection (DI, внедрение зависимостей) — способ передать компоненту нужный сервис извне, вместо того чтобы создавать его самостоятельно внутри компонента. Это уменьшает связанность: компонент зависит от контракта сервиса, а создание, конфигурация и область его жизни определяются контейнером или приложением.

```ts
// Angular: сервис запрашивается через DI-контейнер
import { Component, inject } from '@angular/core';
import { StudentApi } from './student-api';

@Component({ /* ... */ })
export class StudentPage {
  private readonly api = inject(StudentApi);
}
```

DI удобен для API-клиентов, логирования, конфигурации и тестовых замен. В тесте реальный `StudentApi` можно заменить mock-реализацией. В небольшом компоненте с одной простой функцией отдельный контейнер не нужен: достаточно обычной передачи функции или props. DI не означает, что бизнес-логика должна быть глобальной.

**Опора на лекцию:** зависимости и разделение ответственности в компонентном приложении. **Дополнение:** пример синтаксиса Angular приведён по [официальному руководству DI](https://angular.dev/guide/di).

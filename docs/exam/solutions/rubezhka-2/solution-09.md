# 09. Reconciliation и key при рендеринге списков. Почему индекс массива может быть плохим ключом?

> Развёрнутый ответ из прежнего комплекта сохранён. Формулировка сверена с оригинальным PDF. Источники: лекции №2–11 и REST.pdf ([каталог](../../../../lectures/README.md)); дополнительные пояснения к API отмечены в ответе.

Reconciliation — сопоставление предыдущего описания интерфейса с новым после изменения данных. Фреймворк решает, какие элементы сохранить, обновить, переместить или удалить. `key` помогает связать компонент списка с конкретной записью между рендерами.

```jsx
students.map(student => <StudentRow key={student.id} student={student} />)
```

Индекс массива — плохой ключ для списка, который сортируется, фильтруется или меняет состав. После удаления первой записи индексы сдвигаются, и фреймворк может связать введённый текст, фокус или локальное состояние строки с другой записью. Ключ должен быть уникальным среди соседей и стабильным во времени; обычно это постоянный ID данных. Не создавайте `Math.random()` при каждом рендере.

**Опора на лекцию:** компонентный рендеринг и идентичность элементов. **Дополнение:** правила `key` — [официальная документация React](https://react.dev/learn/rendering-lists).

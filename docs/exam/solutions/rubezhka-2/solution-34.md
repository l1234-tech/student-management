# 34. Hash Routing и History API. Отличия и требования к серверу.

> Развёрнутый ответ из прежнего комплекта сохранён. Формулировка сверена с оригинальным PDF. Источники: лекции №2–11 и REST.pdf ([каталог](../../../../lectures/README.md)); дополнительные пояснения к API отмечены в ответе.

Hash routing хранит маршрут после `#`, например `/#/students/42`. Фрагмент не отправляется серверу как часть HTTP-пути, поэтому простая статическая раздача часто работает без настройки серверных маршрутов. URL выглядит менее чисто, а часть браузерных функций фрагмента уже занята.

History API позволяет использовать обычный путь `/students/42`; router меняет историю через `pushState`/`replaceState` и обрабатывает `popstate`. Но при прямом запросе такого URL сервер должен вернуть SPA shell (или обработать маршрут на сервере). Без fallback перезагрузка страницы может дать 404. Оба варианта требуют, чтобы router корректно восстанавливал состояние при Back/Forward.

**Опора на лекцию:** навигация SPA и маршрутизация. **Дополнение:** [MDN History API](https://developer.mozilla.org/en-US/docs/Web/API/History_API) и [hash routing](https://developer.mozilla.org/en-US/docs/Glossary/Hash_routing).

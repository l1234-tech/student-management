# 16. Virtual DOM и reconciliation. Как изменения состояния превращаются в изменения интерфейса.

> Развёрнутый ответ из прежнего комплекта сохранён. Формулировка сверена с оригинальным PDF. Источники: лекции №2–11 и REST.pdf ([каталог](../../../../lectures/README.md)); дополнительные пояснения к API отмечены в ответе.

Virtual DOM — распространённое название объектов/структур, которыми библиотека описывает желаемое дерево UI в памяти. Когда меняются props или state, компонент формирует новое описание. Reconciliation сопоставляет его с предыдущим описанием и определяет необходимые изменения. На этапе commit библиотека применяет их к реальному DOM, после чего браузер пересчитывает отображение.

Упрощённая последовательность: действие → изменение state → повторное вычисление UI → reconciliation → DOM-обновление. Например, если в таблице студентов изменился только текст имени, библиотека может обновить соответствующий текстовый узел, сохранив остальную структуру. Это не означает, что любой фреймворк всегда строит два полных дерева или что diff автоматически делает все обновления бесплатными: реализация и оптимизации отличаются.

**Опора на лекцию:** лекция 9 о декларативном компонентном рендеринге. **Дополнение:** этапы объясняют общий принцип; детали конкретной библиотеки см. в её документации.

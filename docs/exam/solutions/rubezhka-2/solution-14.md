# 14. Глобальный store: зачем он нужен и как организован на примере Pinia или аналога?

> Развёрнутый ответ из прежнего комплекта сохранён. Формулировка сверена с оригинальным PDF. Источники: лекции №2–11 и REST.pdf ([каталог](../../../../lectures/README.md)); дополнительные пояснения к API отмечены в ответе.

Store нужен для состояния, которым пользуются разные несоседние компоненты или которое должно переживать переходы между страницами: текущая сессия, список студентов, настройки фильтра. Он централизует данные и операции. Локальное состояние формы или раскрытой подсказки обычно лучше оставить рядом с компонентом.

В Pinia store обычно описывает **state** (хранимые данные), **getters** (производные значения) и **actions** (операции изменения/асинхронная логика). Компоненты получают store и вызывают его действия; UI обновляется реактивно.

```js
export const useStudentsStore = defineStore('students', {
  state: () => ({ items: [], status: 'idle' }),
  getters: { count: state => state.items.length },
  actions: {
    async load() {
      this.status = 'loading';
      try { this.items = await api.list(); this.status = 'success'; }
      catch { this.status = 'error'; }
    }
  }
});
```

**Опора на лекцию:** state management и глобальное состояние. **Дополнение:** Pinia `state`, `getters` и `actions` — [официальное руководство](https://pinia.vuejs.org/core-concepts/).

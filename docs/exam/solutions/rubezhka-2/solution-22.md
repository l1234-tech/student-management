# 22. RxJS: mergeMap и switchMap. Как отличается обработка нескольких асинхронных запросов?

> Развёрнутый ответ из прежнего комплекта сохранён. Формулировка сверена с оригинальным PDF. Источники: лекции №2–11 и REST.pdf ([каталог](../../../../lectures/README.md)); дополнительные пояснения к API отмечены в ответе.

Оба оператора превращают входное значение во внутренний Observable, но управляют параллельностью по-разному. `mergeMap` подписывается на внутренний поток каждого значения и объединяет их результаты. Несколько запросов могут выполняться параллельно, а завершаться в любом порядке. `switchMap` при новом входном значении отписывается от предыдущего внутреннего потока и оставляет только последний.

Поиск по строке обычно использует `switchMap`: важен результат для самого свежего ввода. Независимая загрузка деталей для каждого выбранного элемента может требовать `mergeMap`, если нужно сохранить все результаты. Для строго последовательных операций есть `concatMap`, для игнорирования новых значений на время текущей операции — `exhaustMap`.

**Опора на лекцию:** операторы RxJS. **Дополнение:** официальная спецификация [mergeMap](https://rxjs.dev/api/operators/mergeMap) и [switchMap](https://rxjs.dev/api/operators/switchMap).

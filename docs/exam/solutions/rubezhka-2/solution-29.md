# 29. Редактирование студента через REST API в SPA. Опишите путь от отправки формы до обновления списка: HTTP-запрос, обработка ответа и ошибок.

> Развёрнутый ответ из прежнего комплекта сохранён. Формулировка сверена с оригинальным PDF. Источники: лекции №2–11 и REST.pdf ([каталог](../../../../lectures/README.md)); дополнительные пояснения к API отмечены в ответе.

Типичный поток: пользователь меняет поля → форма выполняет клиентскую проверку → отправляет `PUT` или `PATCH /api/students/{id}` с JSON и авторизационными данными → API проверяет права, формат и бизнес-ограничения → сервер возвращает обновлённую запись/статус → клиент обновляет store или повторно загружает список. При ошибке форма сохраняет ввод и показывает понятное сообщение; сетевой сбой нужно отличать от ошибки валидации и отсутствия записи.

После ответа можно заменить соответствующий элемент в store по ID, чтобы не перезагружать всю страницу. Однако серверный ответ — источник окончательного значения, поскольку он может нормализовать данные или вычислить поля. Кнопку отправки обычно блокируют на время запроса, но защита от повторной операции должна учитывать и повторную отправку на сервере.

**Опора на лекцию:** SPA, REST и формы. **Дополнение:** формат конкретных методов определяется API; общее понятие HTTP описывает [MDN HTTP](https://developer.mozilla.org/en-US/docs/Web/HTTP).

# 39. Слои архитектуры SPA: Router, Pages, Features, Domain Model, API Client и Shared.

> Развёрнутый ответ из прежнего комплекта сохранён. Формулировка сверена с оригинальным PDF. Источники: лекции №2–11 и REST.pdf ([каталог](../../../../lectures/README.md)); дополнительные пояснения к API отмечены в ответе.

Это один из способов группировки кода по роли. **Router** связывает URL с экраном. **Pages** собирают страницу из возможностей. **Features** реализуют пользовательские сценарии, например поиск или редактирование студента. **Domain Model** описывает предметные данные и правила. **API Client** инкапсулирует HTTP и преобразование ответов. **Shared** хранит действительно общие элементы: базовые UI-компоненты, утилиты и типы.

Например, страница студентов получает данные из `students` feature; feature вызывает доменную операцию или API-клиент; отображает `StudentList` из общих UI-блоков. Такой разрез помогает направить зависимости к стабильным контрактам и не дублировать HTTP-код по компонентам. Названия и число слоёв не являются обязательным стандартом: не нужно создавать пустые папки, если проект мал.

**Опора на лекцию:** архитектура SPA и компонентное разбиение. **Дополнение:** схема слоёв — практический вариант организации, а не единственно возможная структура.

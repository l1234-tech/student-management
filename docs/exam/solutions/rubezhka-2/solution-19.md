# 19. Svelte и компилируемая реактивность. Чем подход отличается от Virtual DOM?

> Развёрнутый ответ из прежнего комплекта сохранён. Формулировка сверена с оригинальным PDF. Источники: лекции №2–11 и REST.pdf ([каталог](../../../../lectures/README.md)); дополнительные пояснения к API отмечены в ответе.

Svelte компилирует компонентный код в JavaScript, который обновляет DOM в ответ на изменения состояния. В классическом описании Svelte это противопоставляется рантайм-подходу Virtual DOM, где библиотека во время работы сравнивает описания интерфейса. В актуальном Svelte 5 реактивность в runes mode задаётся, например, `$state` и `$derived`; компилятор анализирует зависимости.

```svelte
<script>
  let count = $state(0);
  let doubled = $derived(count * 2);
</script>

<button onclick={() => count++}>{doubled}</button>
```

Главное различие — где выполняется работа по отслеживанию изменений: часть работы переносится в компиляцию, а не решается общим runtime diff-алгоритмом. Это не означает, что Svelte не имеет runtime-кода или что Virtual DOM всегда медленнее: итог зависит от приложения, реализации и измерений.

**Опора на лекцию:** сравнение компонентных подходов. **Дополнение:** синтаксис runes и `$derived` — [документация Svelte](https://svelte.dev/docs/svelte/$derived).

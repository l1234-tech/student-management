# 36. Protected Routes. Чем клиентская защита маршрута отличается от проверки прав на backend?

> Развёрнутый ответ из прежнего комплекта сохранён. Формулировка сверена с оригинальным PDF. Источники: лекции №2–11 и REST.pdf ([каталог](../../../../lectures/README.md)); дополнительные пояснения к API отмечены в ответе.

Protected route — клиентская проверка перед показом страницы: есть ли сессия и подходит ли роль пользователя. Она улучшает навигацию и UX: неавторизованного пользователя можно отправить на `/login`, а пользователя без роли — показать экран 403.

Это не граница безопасности. Клиентский код можно изменить, а API вызвать напрямую. Поэтому backend обязан проверять аутентификацию и полномочия при каждом защищённом запросе, включая конкретный объект и действие. UI guard только помогает не показывать заведомо недоступный интерфейс и не заменяет серверную авторизацию.

**Опора на лекцию:** маршруты SPA и роли. **Дополнение:** правило авторизации должно быть реализовано на сервере независимо от состояния интерфейса.

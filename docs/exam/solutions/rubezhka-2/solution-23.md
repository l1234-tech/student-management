# 23. Клиентская навигация в SPA. Как изменяются URL и содержимое страницы без полной перезагрузки HTML-документа?

> Развёрнутый ответ из прежнего комплекта сохранён. Формулировка сверена с оригинальным PDF. Источники: лекции №2–11 и REST.pdf ([каталог](../../../../lectures/README.md)); дополнительные пояснения к API отмечены в ответе.

Router перехватывает внутреннюю навигацию, сопоставляет URL с маршрутом, обновляет историю браузера и отображает нужную страницу или компонент. Данные для страницы могут быть загружены отдельно через API. При обычном переходе внутри приложения браузер не получает новый HTML-документ целиком.

History API позволяет вызвать `history.pushState()`/`replaceState()` и обработать переходы назад/вперёд через `popstate`; router связывает эти события с маршрутом. При прямом открытии `/students/42` сервер должен вернуть приложение или обработать URL маршрута, иначе пользователь получит 404 ещё до запуска JavaScript. Ссылки должны сохранять доступность и базовое поведение, а не быть только кликабельными `div`.

**Опора на лекцию:** лекция 8, SPA и навигация. **Дополнение:** [History API](https://developer.mozilla.org/en-US/docs/Web/API/History_API/Working_with_the_History_API).

# 7. Java: ООП, классы, интерфейсы и исключения

## 7.1. Java и компиляция

Java — статически типизированный язык программирования. Тип переменной известен при компиляции, а компилятор проверяет многие ошибки до запуска.

Обычно исходный файл `.java` компилируется в байткод `.class`, который выполняет JVM (Java Virtual Machine). **JDK** — комплект разработчика, включающий инструменты, в том числе компилятор. **JRE** традиционно означает среду для запуска Java-приложений; в современных дистрибутивах её состав и отдельная поставка зависят от версии.

Упрощённо:

```text
Source code (.java)
       ↓ javac
Bytecode (.class)
       ↓ JVM
Выполнение программы
```

## 7.2. Классы и объекты

**Класс** — описание структуры и поведения объектов. **Объект** — экземпляр класса в памяти. **Поле** хранит состояние, **метод** описывает поведение, **конструктор** инициализирует новый объект.

```java
public class Student {
    private final long id;
    private String name;

    public Student(long id, String name) {
        this.id = id;
        this.name = name;
    }

    public long getId() {
        return id;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }
}
```

- `private` скрывает поле от прямого доступа извне класса.
- `final` у поля запрещает повторное присваивание после инициализации.
- `this.id` — поле текущего объекта; `id` справа — параметр конструктора.
- Конструктор имеет имя класса и не объявляет тип возвращаемого значения.
- Getter возвращает значение, setter меняет его.

## 7.3. Инкапсуляция

**Инкапсуляция** — объединение данных и поведения в классе и контроль доступа к внутреннему состоянию. Она позволяет не разрешать произвольные изменения, а предоставлять методы, которые поддерживают корректность объекта.

Например, вместо открытого поля `age` можно сделать приватное поле и метод `setAge`, который запрещает отрицательный возраст. Тогда правило хранится рядом с данными, а не дублируется во всех местах использования.

## 7.4. Четыре идеи ООП

- **Инкапсуляция** — скрытие внутреннего состояния и контроль доступа.
- **Наследование** — создание класса на основе другого класса, когда отношение «является разновидностью» действительно уместно.
- **Полиморфизм** — возможность работать с объектами разных реализаций через общий тип/интерфейс.
- **Абстракция** — выделение существенных свойств и сокрытие неважных деталей.

Наследование не нужно применять автоматически. Часто композиция (объект содержит другой объект) гибче, чем длинная иерархия классов.

## 7.5. Интерфейс и реализация

**Интерфейс** определяет контракт: какие операции доступны. Класс, реализующий интерфейс, предоставляет конкретное поведение.

```java
public interface StudentRepository {
    Student findById(long id);
}
```

```java
public class InMemoryStudentRepository implements StudentRepository {
    @Override
    public Student findById(long id) {
        // Учебный пример: реальный поиск здесь не реализован.
        return null;
    }
}
```

Пользователь интерфейса зависит от контракта, а не от конкретного способа хранения. Позже реализацию можно заменить, например с in-memory хранилища на базу данных, если контракт остаётся подходящим.

## 7.6. Полиморфизм

```java
interface Notifier {
    void send(String message);
}

class EmailNotifier implements Notifier {
    public void send(String message) {
        System.out.println("Email: " + message);
    }
}

class ConsoleNotifier implements Notifier {
    public void send(String message) {
        System.out.println("Console: " + message);
    }
}
```

Код, который получает `Notifier`, может вызвать `send`, не зная, какая реализация передана. Это снижает связанность и облегчает тестирование.

## 7.7. Модификаторы доступа

- `public` — доступен из других классов, где это допускают правила языка и модулей.
- `protected` — доступ в том же пакете и в подклассах по правилам Java.
- без модификатора (package-private) — доступ внутри того же пакета.
- `private` — доступ внутри класса, где объявлен член.

Не следует делать все поля public: это открывает внутреннее состояние и усложняет соблюдение инвариантов.

## 7.8. Исключения

**Исключение** — объект, сигнализирующий об ошибочной или особой ситуации во время выполнения.

```java
try {
    int value = Integer.parseInt("abc");
} catch (NumberFormatException exception) {
    System.out.println("Строка не является числом");
}
```

- `try` содержит код, который может выбросить исключение.
- `catch` перехватывает соответствующий тип.
- `throw` явно выбрасывает исключение.
- `throws` в сигнатуре метода объявляет, что метод может передать исключение вызывающему коду.

**Checked exceptions** проверяются компилятором: их нужно обработать или объявить в `throws`. **Unchecked exceptions** — наследники `RuntimeException` и `Error`; компилятор не требует объявлять их. Не нужно ловить любой Exception без причины: обрабатывай ситуацию там, где можешь сделать что-то осмысленное.

## 7.9. Коллекции и generics

Коллекции — объекты для хранения групп значений. Частые интерфейсы:
- `List<T>` — упорядоченная последовательность, допускающая повторения;
- `Set<T>` — набор уникальных элементов;
- `Map<K, V>` — соответствия ключей значениям.

**Generics** — параметризация типов. Например, `List<Student>` описывает список студентов и позволяет компилятору проверять типы элементов.

```java
List<String> names = new ArrayList<>();
names.add("Анна");
names.add("Иван");
```

Использование коллекций вместо сырых типов помогает находить ошибки типов на этапе компиляции.

## 7.10. equals и ==

Для примитивов `==` сравнивает значения. Для ссылочных типов `==` сравнивает, указывают ли ссылки на один и тот же объект. Метод `equals` предназначен для логического сравнения содержимого, если класс корректно его переопределяет.

Для строк обычно используют `str1.equals(str2)`, а не `str1 == str2`. Если `str1` может быть `null`, безопаснее, например, `"text".equals(str1)`.

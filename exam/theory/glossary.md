# Словарь терминов веб-разработки

Краткие определения для повторения. Подробные объяснения и примеры находятся в тематических главах.

| Термин | Значение |
|---|---|
| API | Контракт взаимодействия между программами |
| Backend | Серверная логика приложения |
| Bean | Объект, которым управляет Spring-контейнер |
| Browser / браузер | Программа для отображения и взаимодействия с веб-ресурсами |
| CORS | Механизм разрешения браузерных запросов между разными origin |
| CRUD | Create, Read, Update, Delete |
| CSS | Язык описания внешнего вида документа |
| CSRF | Атака с использованием полномочий браузера для нежелательного запроса |
| DTO | Объект передачи данных |
| DI | Передача зависимостей объекту извне |
| DOM | Объектное представление документа в браузере |
| DNS | Система разрешения доменных имён |
| Entity | Сущность предметной области; в JPA — объект, отображаемый на БД |
| Endpoint | Конкретная операция API, обычно путь вместе с HTTP-методом |
| Frontend | Пользовательская часть приложения |
| HTTP | Протокол запросов и ответов Web |
| HTTPS | HTTP поверх защищённого TLS-соединения |
| IoC | Принцип передачи управления созданием/связыванием объектов контейнеру или фреймворку |
| JSON | Текстовый формат структурированных данных |
| JWT | Формат токена для передачи claims, часто подписанного |
| ORM | Сопоставление объектов программы с реляционными данными |
| Promise | Объект, представляющий будущий результат асинхронной операции |
| REST | Архитектурный стиль, часто используемый для построения Web API |
| SPA | Приложение, в котором основные переходы происходят без полной перезагрузки документа |
| SQL | Язык запросов к реляционным данным |
| State | Изменяемые данные, от которых зависит UI или поведение компонента |
| TLS | Протокол защиты сетевого соединения |
| URL | Адрес ресурса |
| Validation | Проверка данных на соответствие требованиям |
| View / Controller | Обработчик запроса или слой представления; точный смысл зависит от архитектуры |
| Аутентификация | Проверка, кто пользователь |
| Авторизация | Проверка, какие действия пользователю разрешены |
| База данных | Организованное хранилище данных |
| Браузерный origin | Комбинация схемы, домена и порта |
| Внешний ключ | Ограничение, связывающее запись с другой записью |
| Зависимость | Объект/компонент, необходимый другому компоненту |
| Контейнер | Изолированное окружение запуска приложения; в Docker — экземпляр образа |
| Куки / cookie | Небольшие данные браузера, которые могут отправляться серверу |
| Миграция | Версионируемое изменение схемы БД |
| Модель | Представление данных; конкретный смысл зависит от MVC/MVT/ORM |
| Модуль JS | Файл с импортами/экспортами |
| Образ Docker | Шаблон для создания контейнера |
| Параметр пути | Значение, передаваемое в сегменте URL, например /students/42 |
| Параметр запроса | Значение после ? в URL, например ?group=R3222 |
| Первичный ключ | Уникально идентифицирует запись таблицы |
| Репозиторий | Слой/абстракция доступа к данным |
| Сериализация | Преобразование данных в формат передачи/хранения |
| Сессия | Серверное состояние взаимодействия пользователя с приложением |
| Состояние HTTP | Код результата обработки HTTP-запроса |
| Транзакция | Группа операций, выполняемая как единое целое |
| Фреймворк | Набор инструментов и соглашений, задающих структуру приложения |
| Хеширование пароля | Преобразование пароля специализированным алгоритмом для безопасной проверки |
| Компонент | Самостоятельная повторно используемая часть UI |
| Экземпляр | Конкретный объект, созданный на основе класса |
| Исключение | Объект/механизм сообщения об ошибке или особой ситуации |

## Термины, которые часто путают

- **Интернет ≠ Web**: инфраструктура сетей и система веб-ресурсов.
- **Сайт ≠ API**: сайт обычно рассчитан на человека, API — на взаимодействие программ; один продукт может иметь оба.
- **Аутентификация ≠ авторизация**: кто ты и что тебе разрешено.
- **401 ≠ 403**: обычно нет подходящей аутентификации против отказа в доступе.
- **Content-Type ≠ Accept**: формат отправляемого тела против предпочитаемого формата ответа.
- **PUT ≠ PATCH**: полная замена против частичного изменения по обычному REST-соглашению.
- **Promise ≠ async-функция**: async-функция возвращает Promise, а Promise — объект результата асинхронной операции.
- **JPA ≠ Hibernate**: спецификация/контракт против конкретной реализации.
- **Entity ≠ DTO**: внутренняя модель хранения против объекта передачи данных.
- **DI ≠ IoC**: DI — конкретный механизм, IoC — более общий принцип.
- **Образ ≠ контейнер**: шаблон против запущенного экземпляра.
- **Проверка frontend ≠ безопасность backend**: клиентский код можно обойти.

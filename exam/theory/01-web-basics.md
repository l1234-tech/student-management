# 1. Интернет, Web, сайты, веб-приложения и API

## 1.1. Интернет

**Интернет** — глобальная система взаимосвязанных компьютерных сетей. Устройства обмениваются данными по согласованным правилам — сетевым протоколам. Интернет — инфраструктура, а не один сайт или программа.

Основные понятия:

- **Клиент** — программа или устройство, которое инициирует запрос: например, браузер.
- **Сервер** — программа/компьютер, который принимает запросы и возвращает данные или результат. Один компьютер может одновременно быть клиентом и сервером в разных взаимодействиях.
- **IP-адрес** — адрес узла в IP-сети.
- **DNS** — система, которая помогает преобразовать доменное имя вроде `example.com` в IP-адрес.
- **Порт** — числовой идентификатор сетевой службы на узле. Например, сервер разработки часто слушает порт 8000.
- **Протокол** — правила формата и обмена сообщениями. Примеры: IP, TCP, HTTP, HTTPS.

Когда пользователь вводит адрес сайта, браузер обычно получает IP-адрес через DNS, устанавливает сетевое соединение, а затем отправляет HTTP-запрос серверу. На практике детали могут различаться из-за кэширования, HTTP/3 и других механизмов.

## 1.2. Что такое Web

**World Wide Web (WWW, Web)** — система связанных ресурсов, доступ к которым обычно осуществляется через браузер по HTTP или HTTPS. Web использует Интернет, но не равен всему Интернету.

Интернет также используется для электронной почты, голосовой связи, игр, передачи файлов и других сервисов. Поэтому утверждение «Интернет и Web — одно и то же» неверно.

### Участники взаимодействия

1. **Браузер** отображает страницы, выполняет JavaScript и отправляет запросы.
2. **Web-сервер** принимает HTTP-запросы. Иногда он сразу отдаёт статические файлы, иногда передаёт запрос backend-приложению.
3. **Backend** выполняет серверную логику: проверяет данные, применяет правила, обращается к БД.
4. **База данных (БД)** хранит структурированные данные.
5. **Внешний сервис** — например, платёжная система или сервис авторизации, с которым backend может взаимодействовать.

Упрощённая схема:

```text
Пользователь
    ↓
Браузер (HTML/CSS/JavaScript)
    ↓ HTTP-запрос
Сервер / Backend
    ↓ SQL-запрос
База данных
    ↑ результат
Backend → HTTP-ответ → Браузер → отображение результата
```

Это логические роли: в небольшом проекте несколько ролей могут работать на одном компьютере.

## 1.3. Сайт и веб-приложение

**Сайт** — набор связанных веб-страниц и ресурсов под общим адресом или доменом. **Веб-приложение** — программа, которой пользователь пользуется через веб-интерфейс и которая выполняет действия, обрабатывает состояние или данные.

Граница не строгая: сайт может включать интерактивные приложения.

| Пример | Что преобладает |
|---|---|
| Страница с информацией о компании | Публикация контента |
| Онлайн-магазин | Каталог, корзина, оформление заказа |
| Личный кабинет студента | Работа с личными данными и действиями |
| Панель управления | Управление объектами и настройками |

Ключевое отличие — не «есть кнопки или нет», а назначение и характер взаимодействия. Современный сайт может быть очень интерактивным.

## 1.4. Frontend и backend

**Frontend** — часть приложения, с которой непосредственно взаимодействует пользователь. В вебе это часто HTML, CSS и JavaScript, выполняющиеся в браузере.

- **HTML** описывает структуру и смысл элементов.
- **CSS** задаёт внешний вид и расположение.
- **JavaScript** добавляет поведение: обработчики событий, проверки, запросы к серверу и обновление интерфейса.

**Backend** — серверная часть. Она принимает запросы, проверяет права и данные, применяет бизнес-правила, работает с БД и формирует ответы.

Например, кнопка «Добавить студента» на frontend собирает данные формы. Backend должен независимо проверить эти данные и сохранить запись. Проверки только в браузере недостаточно: клиент можно обойти или подменить запрос.

## 1.5. API

**API (Application Programming Interface)** — определённый интерфейс, через который одна программа взаимодействует с другой. API описывает доступные операции, параметры, формат результата и ошибки.

**Web API** — API, доступный по веб-протоколам, часто по HTTP. Например:

- `GET /api/students` — получить список студентов;
- `GET /api/students/42` — получить студента с идентификатором 42;
- `POST /api/students` — создать студента.

API — это не обязательно сайт с видимыми страницами. Его клиентом могут быть браузер, мобильное приложение, другой backend или тестовый инструмент.

**Endpoint (конечная точка)** — конкретный адрес и операция API, например `GET /api/students`. Один путь может поддерживать разные HTTP-методы, поэтому путь и метод вместе часто определяют операцию.

## 1.6. Что происходит при загрузке страницы

Предположим, пользователь открывает `https://example.com/students`.

1. Браузер разбирает URL: схема `https`, домен `example.com`, путь `/students`.
2. DNS помогает найти адрес сервера.
3. Браузер устанавливает защищённое соединение.
4. Отправляется HTTP-запрос.
5. Сервер возвращает HTML или иной ответ.
6. Браузер разбирает HTML и при необходимости загружает CSS, JavaScript, изображения и шрифты.
7. JavaScript может выполнить дополнительные запросы к API.
8. Backend при необходимости обращается к БД и возвращает данные.
9. Браузер обновляет интерфейс.

Это модель для понимания. Кэш, CDN, service worker и другие механизмы могут менять последовательность и уменьшать количество запросов.

## 1.7. URL, URI и домен

**URL (Uniform Resource Locator)** — адрес ресурса, включающий способ доступа и местоположение. Пример:

```text
https://example.com:443/api/students?group=R3222#results
```

- `https` — схема;
- `example.com` — доменное имя;
- `443` — порт (стандартный для HTTPS, поэтому обычно опускается);
- `/api/students` — путь;
- `?group=R3222` — строка запроса с параметрами;
- `#results` — фрагмент страницы, обычно обрабатываемый браузером.

**Домен** — читаемое имя, используемое в DNS. **Путь** — часть адреса, указывающая на ресурс или маршрут приложения. **Query-параметры** часто используются для фильтрации, сортировки и пагинации.

## 1.8. Частые ошибки в объяснениях

- Интернет — инфраструктура сетей; Web — одна из систем, работающих поверх неё.
- Сайт не обязательно статический, а веб-приложение не обязательно имеет отдельный домен.
- API — интерфейс взаимодействия программ, а не обязательно графический интерфейс.
- Frontend может проверять форму для удобства, но backend обязан проверять данные и права повторно.
- Браузер не обращается к базе данных напрямую в обычной архитектуре: запрос проходит через серверный слой.

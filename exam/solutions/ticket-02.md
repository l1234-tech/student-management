# Решение билета №2

## 1. Stateless
Каждый запрос должен содержать достаточно сведений для своей обработки; сервер не полагается на неявное состояние предыдущего запроса конкретного клиента. Это не означает отсутствие базы данных: система может хранить пользователей, студентов и refresh-сессии.

## 2. Аутентификация и авторизация
Аутентификация подтверждает личность пользователя. Авторизация определяет разрешённые действия. Backend проверяет роль при каждом защищённом запросе: клиент можно модифицировать или обойти, отправив HTTP-запрос напрямую. Скрытая кнопка — только удобство интерфейса, не контроль доступа.

## 3. Практика
~~~js
export async function getStudent(id) {
  const response = await fetch("/api/students/" + encodeURIComponent(id));
  if (!response.ok) {
    throw new Error("Не удалось получить студента: HTTP " + response.status);
  }
  return response.json();
}
~~~

Вызывающий код должен обработать ошибку через try/catch. В реальном API также следует определить поведение при некорректном JSON и формат ошибок сервера.

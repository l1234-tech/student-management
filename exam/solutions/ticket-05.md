# Решение билета №5

## 1. REST
REST — архитектурный стиль взаимодействия через ресурсы и единый интерфейс. В типичном HTTP API GET читает, POST создаёт, PUT заменяет, PATCH частично изменяет, DELETE удаляет. Реальный контракт API должен документировать точную семантику.

## 2. Path и query
Path-параметр — часть пути, например /students/123; обычно идентифицирует ресурс. Query-параметр идёт после ?, например /students?group=M3301; часто задаёт фильтрацию, сортировку или пагинацию.

## 3. Пример
GET /api/students → 200; GET /api/students/123 → 200 или 404; POST /api/students → 201; PATCH /api/students/123 → 200/204; DELETE /api/students/123 → 204; конфликт уникальности → 409. Конкретный контракт может выбирать некоторые статусы иначе, но должен быть последовательным.

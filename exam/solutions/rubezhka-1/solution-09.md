# Рубежка №1 — билет 9: точные условия и подробные решения

## Теоретический вопрос 17 — условие из файла

> Чем async/await полезен по сравнению с цепочкой then и почему он не превращает асинхронный сетевой запрос в блокирующий вызов всего браузера?

### Подробный ответ

`async` делает функцию возвращающей Promise; `await` позволяет писать продолжение после асинхронной операции в линейном стиле, не превращая сам запрос в синхронный. Когда выполнение доходит до `await`, продолжение данной async-функции приостанавливается до завершения Promise, а главный поток браузера может выполнять другие задачи — отрисовывать интерфейс, принимать события и обрабатывать другие завершённые операции.

По сравнению с `.then()` синтаксис `async/await` часто проще читать при нескольких зависимых действиях, а ошибки можно обрабатывать обычным `try/catch`. Однако механизм основан на Promise и не устраняет синхронные вычисления. Если внутри async-функции выполнить большой CPU-bound цикл или вызвать блокирующий API, поток всё равно будет занят.

**Прямой ответ:** `async/await` улучшает читаемость асинхронного кода, а ожидание Promise не блокирует всё приложение. Но `async` сам по себе не делает блокирующий код неблокирующим и не ускоряет тяжёлые вычисления.

## Теоретический вопрос 18 — условие из файла

> Сравните localStorage, sessionStorage и cookie по длительности хранения, доступности из JavaScript и отправке на сервер. Как выбор влияет на веб-приложение?

### Подробный ответ

| Механизм | Время хранения | Доступ из JavaScript | Автоматическая отправка серверу |
|---|---|---|---|
| `localStorage` | Сохраняется между вкладками и перезапусками, пока не очищен | Да, для того же origin | Нет |
| `sessionStorage` | Обычно на срок жизни сессии конкретной вкладки | Да, для того же origin | Нет |
| Cookie | По `Expires`/`Max-Age` или до завершения сессии браузера | Да, если не задан `HttpOnly` | Да, если URL и атрибуты cookie подходят |

Cookie может иметь атрибуты `Secure`, `HttpOnly`, `SameSite`, `Path` и `Domain`. `HttpOnly` не позволяет читать cookie из JavaScript, снижая риск её кражи через XSS; `Secure` ограничивает отправку защищённым соединением; `SameSite` помогает управлять межсайтовой отправкой. Cookie часто используют для сессии, но автоматическая отправка аутентификационной cookie означает, что нужно учитывать CSRF.

`localStorage` удобен для долговременных пользовательских настроек, но не подходит для секретов, которые можно украсть при XSS. `sessionStorage` годится для временных данных одной вкладки. Выбор зависит от срока жизни, доступности на сервере и модели угроз; механизмы не взаимозаменяемы.

## Практическое задание 9 — условие из файла

> Напишите JavaScript-код, который при запуске последовательно выводит в консоль A, D, B, C: два синхронных вывода, один callback промиса и один callback setTimeout(..., 0). Используйте очередь микрозадач и задач.

### Решение

```js
console.log("A");
console.log("D");

Promise.resolve().then(() => console.log("B"));
setTimeout(() => console.log("C"), 0);
```

### Почему вывод именно A, D, B, C

1. `console.log("A")` и `console.log("D")` синхронны, выполняются прямо сейчас и идут по порядку.
2. `.then(...)` регистрирует callback Promise как микрозадачу.
3. `setTimeout(..., 0)` ставит callback в очередь задач; нулевая задержка не означает немедленное выполнение.
4. После завершения текущего синхронного стека event loop обрабатывает очередь микрозадач перед переходом к следующей задаче. Поэтому `B` появляется раньше `C`.

Итог: `A`, `D`, `B`, `C`. Важно различать синхронный стек, очередь микрозадач (Promise callbacks) и очередь задач (таймеры).

## Теория 1. Симметричная и асимметричная криптография в TLS

Симметричные алгоритмы эффективно шифруют большие объёмы данных одним сеансовым ключом. Асимметричная криптография и цифровые подписи помогают установить защищённый сеанс и подтвердить идентичность сервера. Современный TLS использует согласование ключей (обычно на основе эфемерного Diffie–Hellman) и сертификат/подпись для аутентификации, затем шифрует данные симметрическим алгоритмом.

Сертификат связывает имя сервера с публичным ключом и подписан доверенным удостоверяющим центром. Клиент проверяет цепочку доверия, срок действия и соответствие имени. HTTPS защищает данные в пути, но не проверяет бизнес-права пользователя и не делает безопасным уязвимый backend.

## Теория 2. Persistence context и dirty checking

Persistence context — контекст управляемых JPA-сущностей, отслеживающий их идентичность и изменения. В пределах контекста одна запись обычно представлена одним управляемым объектом. Если его поле изменилось, ORM может заметить это через dirty checking и сформировать UPDATE при flush.

Flush синхронизирует изменения с БД через SQL, но сам по себе не равен commit транзакции. Транзакция определяет границы согласованного изменения и возможность rollback. Если объект detached или изменение произошло вне управления persistence context, автоматическое dirty checking может не сработать.

## Практика. Требовать HTTPS для всех запросов

```java
@Bean
SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    return http
        .requiresChannel(channel ->
            channel.anyRequest().requiresSecure())
        .build();
}
```

`requiresSecure()` требует защищённый канал. TLS при этом должен быть настроен на сервере или корректном reverse proxy, а прокси-заголовки нужно обрабатывать доверенно. В реальном приложении этот фрагмент объединяют с остальными правилами аутентификации/авторизации, а не создают второй конфликтующий SecurityFilterChain.

## Прямые теоретические ответы

**Прямой ответ на вопросы 51–52.** TLS сочетает асимметричную и симметричную криптографию, потому что у них разные сильные стороны. Сертификат связывает публичный ключ с именем сервера и подписан центром сертификации, которому клиент доверяет; проверка сертификата и имени домена помогает удостовериться, что клиент общается с нужным сервером. Асимметричные механизмы помогают установить/согласовать ключи и проверять подписи, а симметричный сеансовый ключ эффективен для шифрования большого объёма данных. Сам сертификат не шифрует весь HTTP-трафик.

Persistence context в ORM отслеживает управляемые сущности в рамках контекста, обычно связанного с EntityManager и транзакцией. Он поддерживает identity map: одинаковая сущность с одним первичным ключом в контексте представлена согласованным управляемым объектом. Dirty checking выявляет изменения полей управляемого объекта; при синхронизации контекста/commit ORM формирует необходимый SQL. Поэтому в типичном JPA-сценарии изменение managed-сущности внутри транзакции может сохраниться без явного вызова `save`; детали зависят от состояния сущности и границ транзакции.

# Рубежка №1 — билет 4: точные условия и подробные решения

## Теоретический вопрос 7 — условие из файла

> Чем отличается DOM от исходного HTML и от BOM? Объясните, почему JavaScript способен менять страницу, не запрашивая заново весь HTML-документ.

### Подробный ответ

HTML — текстовая разметка, полученная браузером или сформированная приложением. Браузер парсит её и создаёт DOM (Document Object Model) — объектное дерево, в котором элементы, атрибуты и текст представлены объектами. JavaScript может находить узлы, создавать новые элементы, изменять текст и атрибуты и удалять узлы. Браузер затем обновляет визуальное представление изменённого дерева.

BOM (Browser Object Model) — интерфейсы к среде браузера: например, `window`, `location`, `history`, `navigator`. DOM описывает документ, BOM — окружение окна и вкладки; в браузере доступ к документу часто получается через `window.document`.

Поэтому для обновления одной строки таблицы не нужно заново получать HTML целиком. JavaScript может изменить соответствующий DOM-узел. Это удобно для интерактивных интерфейсов и одностраничных приложений.

Пример: `document.querySelector("#students")` находит список; `document.createElement("li")` создаёт элемент; `append()` добавляет его в DOM. Это изменение текущего документа, а не повторная загрузка всего HTML.

## Теоретический вопрос 8 — условие из файла

> Как связаны события пользователя, обработчики JavaScript и изменение DOM? Почему визуальная реакция интерфейса должна опираться на актуальное состояние данных, а не только на случайную правку текста?

### Подробный ответ

Событие — сигнал о действии пользователя или состоянии элемента: `click`, `input`, `submit`, `change`. Обработчик — функция, зарегистрированная, например, через `addEventListener`, которая выполняется при событии.

Надёжная последовательность выглядит так: событие → чтение входа → проверка → изменение модели данных → обновление DOM. Источник данных (например, массив студентов) должен быть согласован с интерфейсом. Если изменить только текст в DOM, не обновив состояние, последующий рендер может вернуть старое значение, а данные и экран разойдутся.

Для формы обработчик `submit` часто вызывает `event.preventDefault()`, чтобы остановить обычную отправку браузера и выполнить собственную логику. После проверки форма может отправить запрос API, а интерфейс должен отразить результат сервера — успех или ошибку.

Таким образом, DOM — отображение состояния, а не замена модели данных. При изменении студента лучше обновить данные и затем отобразить их, чтобы разные части интерфейса показывали согласованную информацию.

## Практическое задание 4 — условие из файла

> Напишите HTML-форму добавления студента с полями «ИСУ ID» (положительное целое число, обязательно), «Группа» (строка, обязательно), «Иностранец» (checkbox) и кнопкой отправки. Свяжите каждое поле с label. Отправка — POST на /api/students.

### Решение

```html
<form action="/api/students" method="post">
  <label for="isu-id">ИСУ ID</label>
  <input id="isu-id" name="isu_id" type="number"
         min="1" step="1" required>

  <label for="group">Группа</label>
  <input id="group" name="group" type="text" required>

  <label for="is-foreign">Иностранец</label>
  <input id="is-foreign" name="is_foreign" type="checkbox">

  <button type="submit">Добавить студента</button>
</form>
```

### Подробный разбор

- У формы `action="/api/students"` и `method="post"`, поэтому браузер отправляет форму методом POST на указанный путь.
- `type="number"`, `min="1"`, `step="1"` и `required` задают для ИСУ положительное целое обязательное значение.
- `required` у группы запрещает оставить поле пустым на уровне стандартной браузерной проверки.
- `checkbox` подходит для признака «Иностранец». Если он выключен, стандартная отправка обычно не включает поле в form data; backend должен учитывать это.
- Каждый `label` связан с полем через совпадающие `for` и `id`, что улучшает доступность и позволяет активировать поле нажатием на подпись.

Важное уточнение: нативная форма отправляет данные как form data, а не как JSON. Это решение соответствует условию об HTML-форме и POST. Если контракт API принимает исключительно JSON, нужно перехватить submit JavaScript-кодом и выполнить `fetch` с `Content-Type: application/json`. В любом случае backend обязан повторно валидировать значения.

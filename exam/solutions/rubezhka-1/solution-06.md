## Теория 1. HTML-, JavaScript- и серверная валидация

HTML-валидация — встроенные ограничения элементов формы: `required`, `type="email"`, `min`, `max`, `pattern`. Она проста и сразу сообщает пользователю о типовых ошибках. JavaScript нужен для более сложных предметных правил и кастомных сообщений, а также для проверки нескольких полей совместно.

Но клиент контролируется пользователем: JavaScript можно отключить, форму можно обойти и отправить HTTP-запрос напрямую. Поэтому backend обязан повторить все проверки, от которых зависит корректность и безопасность данных. В лабораторной №1 валидация выполняется на клиенте; в лабораторной №2 сервер проверяет данные повторно через DRF Serializer и бизнес-логику.

Валидация должна проверять тип, формат, диапазон, обязательность и бизнес-ограничения (например, уникальность ИСУ). Не следует считать, что проверка формата заменяет проверку прав доступа.

## Теория 2. Каскад и специфичность CSS

Когда несколько правил задают одно свойство, браузер учитывает каскад: важность и происхождение правила, специфичность селектора, а затем порядок объявления при прочих равных условиях. Упрощённо: inline-стили и правила с `!important` требуют отдельного рассмотрения; среди обычных авторских правил ID-селектор обычно специфичнее класса, а класс специфичнее селектора тега.

Пример:
```css
p { color: black; }
.note { color: blue; }
#warning { color: red; }
```
Элемент `<p id="warning" class="note">` будет красным, потому что `#warning` специфичнее `.note` и `p`. Если два селектора имеют одинаковую специфичность, обычно выигрывает правило, объявленное позже.

Не рекомендуется решать все конфликты бесконечным повышением специфичности: проще поддерживать понятную структуру классов.

## Практика. Адаптивная сетка карточек

```css
.cards {
  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
  gap: 16px;
}

@media (max-width: 700px) {
  .cards {
    grid-template-columns: 1fr;
  }
}
```

По умолчанию контейнер имеет две равные колонки. Media query включается при ширине 700px и меньше, переводя сетку в одну колонку. `gap: 16px` задаёт промежутки между карточками. `minmax(0, 1fr)` помогает колонкам не расширяться из-за длинного содержимого.

## Прямые ответы на теоретические вопросы

**Прямой ответ на вопрос 11:** следует совмещать HTML и JavaScript-валидацию ради удобства, но серверную проверку это не отменяет. HTML помогает сразу отсеивать простые ошибки (`required`, `min`, `step`, `pattern`); JavaScript умеет проверять сложные правила и зависимости между полями. Клиентские проверки можно обойти через DevTools или прямой HTTP-запрос, поэтому backend повторно проверяет тип, диапазон, обязательность, формат, бизнес-ограничения и права пользователя. Валидация корректности данных и авторизация — разные проверки: правильный формат ИСУ не означает, что клиент имеет право изменить запись.

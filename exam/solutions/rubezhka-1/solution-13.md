## Теория 1. Обязанности backend

Backend — не только маршруты REST и не только БД. Он принимает запросы, проверяет входные данные, аутентифицирует клиента, проверяет права, выполняет бизнес-правила, читает и меняет данные, обрабатывает ошибки, пишет логи и формирует HTTP-ответ.

Для студентов: Controller разбирает запрос; Service проверяет правила (например, уникальность ИСУ); Repository работает с хранилищем; обработчик ошибок преобразует исключения в статусы и JSON. БД отвечает за долговременное хранение и ограничения целостности, но не заменяет весь прикладной процесс.

## Теория 2. Decorator и Proxy

Decorator оборачивает объект, добавляя поведение через композицию, обычно сохраняя тот же интерфейс. Например, декоратор репозитория может добавить кэширование или метрики.

Proxy выступает заместителем реального объекта и контролирует доступ к нему: может проверять права, лениво создавать объект или перенаправлять вызов. В Java/Spring динамические прокси применяются инфраструктурой, например для аспектов и транзакционного поведения. Внешне оба делегируют вызовы, но Decorator фокусируется на расширении поведения, а Proxy — на контроле доступа/представлении объекта; конкретная реализация может пересекаться.

## Практика. Repository + Service на Python

```python
class StudentRepository:
    def __init__(self):
        self._students = {}

    def add(self, student):
        self._students[student["isu_id"]] = student

    def get_by_id(self, isu_id):
        return self._students.get(isu_id)


class StudentService:
    def __init__(self, repository):
        self._repository = repository

    def get_student(self, isu_id):
        student = self._repository.get_by_id(isu_id)
        if student is None:
            raise LookupError(f"Student {isu_id} not found")
        return student
```

Сервис получает репозиторий через конструктор, а не создаёт его внутри. Это и есть DI. Для лабораторной это учебный минимальный вариант: реальный слой API должен преобразовать LookupError/доменное исключение в корректный HTTP 404.

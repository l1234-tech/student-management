## Теория 1. Слои и организация по функциональным областям

Слои разделяют тип ответственности: Controller — HTTP, Service — бизнес-правила, Repository — доступ к данным. Организация по функциональным областям группирует вместе всё, что относится к студентам, общежитиям или пользователям, даже если внутри каждой области есть controller/service/repository. Структура только по слоям может мешать, когда проект большой: для изменения одной функции приходится переходить между множеством папок, а классы одной предметной области разнесены далеко друг от друга.

Важнее не конкретная схема папок, а ясные границы ответственности и зависимостей. В наших лабораторных код разделён на представления, сервисы и доступ к данным; при росте проекта можно группировать их по предметным областям.

## Теория 2. Dependency Injection

Dependency Injection (DI) означает, что объект получает необходимые зависимости извне, вместо самостоятельного создания конкретных реализаций. Это уменьшает связанность и позволяет подменять зависимость в тесте.

Пример:
```java
@Service
public class StudentService {
    private final StudentRepository repository;

    public StudentService(StudentRepository repository) {
        this.repository = repository;
    }
}
```
Spring создаёт компонент и передаёт ему репозиторий. Сервис не отвечает за конфигурацию подключения к БД. Конструктор делает обязательную зависимость явной и упрощает unit-тестирование.

## Практика. saveStudent через fetch

```js
async function saveStudent(student) {
  const response = await fetch("/api/students", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "Accept": "application/json"
    },
    body: JSON.stringify(student)
  });

  if (!response.ok) {
    throw new Error(`HTTP error: ${response.status}`);
  }
  return response.json();
}
```

Объект сериализуется в JSON, заголовок Content-Type сообщает серверу формат. `fetch` не бросает исключение только из-за 400/500, поэтому проверяем `response.ok`. При ошибке бросаем Error с кодом статуса, при успехе читаем JSON. Если API может возвращать 204 без тела, этот контракт нужно отдельно учесть; в задании ожидается JSON.

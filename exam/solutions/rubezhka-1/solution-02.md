## Теория 1. Stateless, cookies и узнавание пользователя

HTTP сам по себе stateless: отдельный запрос не содержит обязательной встроенной ссылки на контекст предыдущего запроса. Сервер получает метод, путь, заголовки и, при необходимости, тело и обрабатывает именно этот запрос.

Приложение может связать запросы с одной сессией, если клиент передаёт идентификатор или токен. Например, браузер хранит cookie и автоматически отправляет её согласно атрибутам cookie. Сервер читает идентификатор сессии и находит связанное состояние. Другой вариант — клиент отправляет access token в заголовке Authorization.

Stateless не означает «сервер ничего не хранит»: записи студентов и учётные записи могут лежать в БД. Это означает, что протокол не требует неявной памяти о предыдущем запросе; нужный контекст передаётся или восстанавливается явно.

В проекте лабораторной №3 используются JWT access/refresh и Spring Security; это отличается от простого хранения всего состояния в памяти конкретного HTTP-запроса.

## Теория 2. Safe и idempotent

**Safe** означает, что запрос по своему назначению не должен изменять состояние ресурса. GET — стандартный пример. Это не обещание, что сервер не пишет логи или метрики: речь о запрошенной семантике.

**Idempotent** означает, что многократное выполнение одного и того же запроса имеет тот же целевой эффект, что и однократное. PUT и DELETE считаются идемпотентными по семантике HTTP, хотя ответы могут различаться: первый DELETE может вернуть 204, повторный — 404.

POST часто неидемпотентен: повторный запрос создания может создать две записи. Для критичных операций API иногда применяет ключ идемпотентности или проверку уникальности, например уникального ИСУ ID.

## Практика. Разбор URL через URL API

```js
function getAddressParts(address) {
  const url = new URL(address);
  return {
    host: url.host,
    path: url.pathname,
    sort: url.searchParams.get("sort"),
    fragment: url.hash ? url.hash.slice(1) : ""
  };
}
```

`new URL(address)` разбирает абсолютный URL штатным парсером браузера. `host` содержит имя хоста и, если задан, порт; `pathname` — путь; `searchParams.get("sort")` возвращает значение параметра или `null); `hash` содержит фрагмент вместе с `#`, поэтому `slice(1)` убирает этот символ. В условии сказано «fragment без #»; если фрагмента нет, здесь возвращается пустая строка.

Не следует вручную делить URL по `/`, `?` и `#`: в URL есть правила кодирования, портов и относительных частей, которые уже реализованы парсером.

## Теория 1. HTTPS, JWT, роли и валидация

Эти механизмы закрывают разные риски:
- HTTPS/TLS защищает канал от перехвата и незаметной модификации данных в пути.
- JWT позволяет передать проверяемые claims/идентификацию, если подпись и ограничения токена валидируются.
- Проверка ролей определяет разрешённые действия.
- Серверная валидация проверяет форму и смысл входных данных.

Если оставить только HTTPS, пользователь всё ещё может отправить недопустимые данные или вызвать запрещённую операцию. Подписанный JWT не означает, что у пользователя есть право на любой endpoint. Проверка роли не защищает пароль в сети, если нет TLS. Валидация не подтверждает личность. Защита строится из нескольких независимых слоёв.

## Теория 2. UserDetailsService, PasswordEncoder, AuthenticationProvider

UserDetailsService загружает сведения о пользователе по идентификатору входа (например, логину). PasswordEncoder безопасно сравнивает введённый пароль с сохранённым хешем. AuthenticationProvider объединяет механизм проверки credentials и формирования результата аутентификации.

Просто сравнить две строки недостаточно: в базе должен храниться не открытый пароль, а стойкий хеш с параметрами алгоритма. Provider должен корректно отклонять неверные credentials и передавать результат системе безопасности. В проекте лабораторной №3 используются Spring Security и BCrypt.

## Практика. Изменить группу студента через JPA

```java
@Transactional
public Student changeGroup(long id, String groupName) {
    Student student = studentRepository.findById(id)
        .orElseThrow(() -> new StudentNotFoundException(id));
    student.setGroup(groupName);
    return student;
}
```

Если `student` — managed entity внутри активной транзакции, JPA отслеживает изменение и при flush выполнит UPDATE (dirty checking). Поэтому явный `save` обычно не обязателен для уже загруженной managed-сущности. `save` может быть полезен для другого контракта/репозитория или detached-объекта, но это не универсальное требование. Важно, чтобы транзакция охватывала чтение и изменение и чтобы группа проходила валидацию.

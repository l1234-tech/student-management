## Теория 1. Интернет, веб, сайт, веб-приложение и API

**Интернет** — глобальная сеть сетей и инфраструктура передачи данных. **Веб (WWW)** — сервис поверх интернета, в котором ресурсы связываются URL и передаются в основном по HTTP/HTTPS. Интернет включает и другие сервисы, например электронную почту.

**Сайт** — набор связанных веб-страниц и ресурсов под общим адресом. **Веб-приложение** — программа с пользовательским интерфейсом и логикой: пользователь не только читает содержимое, но и выполняет действия, например создаёт или редактирует студента. **API** — контракт взаимодействия программных компонентов; в нашем проекте frontend отправляет запросы backend и получает структурированные ответы, часто JSON.

Пример: браузер открывает веб-приложение управления студентами через интернет; страница отображает форму, а JavaScript вызывает API для получения или изменения записей. API не обязан иметь собственную визуальную страницу.

## Теория 2. GET, POST, PUT, PATCH, DELETE и CRUD

CRUD — Create, Read, Update, Delete. Типичное соответствие:

| Метод | Типичное назначение | CRUD |
|---|---|---|
| GET | Получить ресурс/список | Read |
| POST | Создать ресурс или выполнить операцию | Create (часто) |
| PUT | Заменить ресурс целиком | Update |
| PATCH | Частично изменить ресурс | Update |
| DELETE | Удалить ресурс | Delete |

Методы не взаимозаменяемы, потому что у них разная семантика. GET по контракту безопасен: не должен запрашивать изменение состояния ресурса. PUT идемпотентен: повторное применение одного и того же запроса должно приводить к тому же целевому состоянию. POST не гарантирует идемпотентность: повтор создания может создать дубликат, если API не предотвращает это.

CRUD — модель операций над данными, а HTTP-метод — семантика протокола. Например, POST может запускать бизнес-операцию, не создающую обычную запись.

## Практика. HTTP/1.1 GET студента с ИСУ ID 42

Запрос:

```http
GET /api/students/42 HTTP/1.1
Host: university.example
Accept: application/json
```

- `GET` — запрос чтения.
- `/api/students/42` — путь к конкретному ресурсу.
- `Host` — имя хоста в HTTP/1.1.
- `Accept: application/json` — клиент предпочитает JSON в ответе.

URL использует HTTPS, но задание просит только сырой HTTP/1.1-запрос. TLS и TCP не записываются в этом фрагменте.

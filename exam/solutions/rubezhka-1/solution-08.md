# Рубежка №1 — билет 8: точные условия и подробные решения

## Теоретический вопрос 15 — условие из файла

> Сравните Function Declaration, Function Expression и arrow function: как способ объявления влияет на hoisting и поведение this?

### Подробный ответ

**Function Declaration** — объявление функции по форме `function f() {}`. В пределах соответствующей области видимости такое объявление доступно до строки, на которой оно написано, поскольку функция инициализируется при подготовке окружения.

**Function Expression** — функция как выражение, например `const f = function () {}`. Само значение появляется при выполнении присваивания. Если для переменной используется `const` или `let`, обращаться к ней до инициализации нельзя из-за temporal dead zone.

**Arrow function** — выражение вида `() => {}`. Она не создаёт собственного `this`, а захватывает его из внешней лексической области; также не имеет собственного `arguments` и не используется как обычный конструктор с `new`.

```js
function declaration() {}
const expression = function () {};
const arrow = () => {};
```

**Прямой ответ:** различия касаются момента доступности объявления и контекста `this`. Для метода объекта обычная функция может получать `this` от способа вызова; стрелочная функция сохраняет внешний `this`, поэтому удобна для callback, но не всегда подходит как метод, которому нужен динамический контекст.

## Теоретический вопрос 16 — условие из файла

> Почему два приложения на одном компьютере, открытые на разных origin, не могут свободно читать DOM и хранилища друг друга? Объясните смысл Same-Origin Policy.

### Подробный ответ

Origin определяется тройкой: схема, хост и порт. Например, `https://example.com` и `http://example.com` отличаются схемой, а `https://example.com` и `https://example.com:8443` отличаются портом, поэтому это разные origin.

Same-Origin Policy — браузерная политика изоляции. Без неё вредоносный сайт мог бы прочитать данные другого открытого сайта, к которому пользователь уже авторизован, и получить доступ к его DOM или данным веб-хранилища. SOP ограничивает чтение документов и защищённых данных другого origin. CORS позволяет серверу разрешить определённый cross-origin доступ к ответам, но не предоставляет безусловный доступ к DOM произвольной другой вкладки.

То, что приложения запущены на одном компьютере, не делает их origin одинаковым: решают схема, хост и порт, а не физическое устройство.

## Практическое задание 8 — условие из файла

> На JavaScript напишите обработчик кнопки #add: он берёт строку из #student-name, создаёт элемент li с введённым ФИО и добавляет его в список #students. Не используйте innerHTML; пустые строки не добавляйте.

### Решение

```js
const addButton = document.querySelector("#add");
const nameInput = document.querySelector("#student-name");
const list = document.querySelector("#students");

addButton.addEventListener("click", () => {
  const fullName = nameInput.value.trim();

  if (fullName === "") {
    return;
  }

  const item = document.createElement("li");
  item.textContent = fullName;
  list.append(item);
  nameInput.value = "";
});
```

### Подробный разбор

1. Получаем ссылки на кнопку, input и список.
2. В обработчике читаем значение input. `trim()` отбрасывает пробелы по краям, поэтому строка из одних пробелов не будет считаться ФИО.
3. Если строка пустая, выходим из обработчика и ничего не добавляем.
4. `createElement("li")` создаёт DOM-элемент.
5. `textContent` вставляет пользовательскую строку именно как текст. В отличие от `innerHTML`, браузер не интерпретирует содержимое как HTML-разметку, что уменьшает риск XSS.
6. `append(item)` добавляет элемент в конец списка; после успешного добавления поле очищается.

Условие требует не использовать `innerHTML`, поэтому пользовательский текст должен вставляться через `textContent` или аналогичный безопасный текстовый API.

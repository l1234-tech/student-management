# Рубежка №1 — билет 5: точные условия и подробные решения

## Теоретический вопрос 9 — условие из файла

> Чем отличаются var, let и const с точки зрения области видимости и переназначения? Почему const не делает содержимое объекта автоматически неизменяемым?

### Подробный ответ

- `var` имеет функциональную область видимости (либо глобальную область вне функции), разрешает повторное объявление в той же области и подвергается hoisting: объявление обрабатывается до выполнения строк кода, а до присваивания значение обычно `undefined`.
- `let` имеет блочную область видимости и допускает переназначение. До объявления переменная находится в temporal dead zone и использовать её нельзя.
- `const` тоже имеет блочную область видимости, но требует начального значения и запрещает переназначить саму переменную после инициализации.

`const` не замораживает объект. Переменная хранит ссылку на объект, и ссылка остаётся постоянной, а свойства объекта могут меняться:

```js
const student = { group: "M3301" };
student.group = "R3222"; // допустимо
// student = {};         // TypeError: переназначать нельзя
```

`Object.freeze(student)` запрещает поверхностное изменение свойств объекта, однако заморозка не становится автоматически глубокой для вложенных объектов. Обычно используют `const` по умолчанию, а `let` — когда необходимо присваивать переменной новое значение.

## Теоретический вопрос 10 — условие из файла

> Почему разметка из одних div может отображаться так же, как семантическая, но хуже подходить для поддержки и доступности? На конкретных элементах объясните роль header, nav, main и footer.

### Подробный ответ

Браузер может отобразить `div` и семантические элементы одинаково при совпадающих CSS-правилах. Но `div` — нейтральный контейнер без самостоятельного смысла; из множества таких контейнеров сложнее понять назначение каждой части страницы.

- `header` — вводная область страницы или раздела, часто содержит название и общую информацию.
- `nav` — блок основных навигационных ссылок.
- `main` — основное содержимое страницы; как правило, на странице один основной `main`.
- `footer` — заключительная информация о странице или разделе, например контакты или ссылки на документы.

Семантическая разметка облегчает чтение исходного кода, поддержку и навигацию вспомогательных технологий, включая скринридеры. Она не заменяет CSS: внешний вид по-прежнему задаётся стилями. Правильная семантика особенно важна, если требуется доступность, а не только пиксельное совпадение с макетом.

## Практическое задание 5 — условие из файла

> Напишите CSS для кнопки .save-btn: базовый цвет берётся из переменной --accent, при наведении появляется подчёркивание текста, при фокусе с клавиатуры — заметная обводка. Определите переменную на :root.

### Решение

```css
:root {
  --accent: #6d4aff;
}

.save-btn {
  background-color: var(--accent);
  color: white;
  border: 0;
  padding: 0.6rem 1rem;
  border-radius: 0.4rem;
}

.save-btn:hover {
  text-decoration: underline;
}

.save-btn:focus-visible {
  outline: 3px solid #222;
  outline-offset: 3px;
}
```

### Подробный разбор

`--accent` — CSS custom property, объявленная в корне документа; она доступна потомкам и позволяет централизованно менять цветовую схему. `var(--accent)` использует её в кнопке. `:hover` срабатывает при наведении указателя и добавляет подчёркивание текста. `:focus-visible` позволяет показать заметную обводку, в частности при клавиатурной навигации. `outline-offset` отделяет рамку от края кнопки.

Не нужно удалять клавиатурный фокус ради внешнего вида: без видимого индикатора пользователю клавиатуры трудно понять, какой элемент выбран. Цвет в примере условный; ключевое требование — использование переменной и псевдоклассов.

## Теория 1. Путь HTTPS-запроса

1. Браузер разбирает URL: схема HTTPS, имя хоста, порт (по умолчанию 443), путь, query и fragment. Fragment обычно не отправляется серверу.
2. DNS разрешает имя хоста в IP-адрес.
3. Клиент устанавливает транспортное соединение, обычно TCP для HTTP/1.1 или HTTP/2. HTTP/3 работает поверх QUIC/UDP.
4. Для HTTPS устанавливается защищённый канал TLS: согласуются криптографические параметры, проверяется сертификат сервера, создаются ключи сессии.
5. Браузер отправляет HTTP-запрос с методом, путём, заголовками и, при необходимости, телом.
6. Веб-сервер/приложение маршрутизирует запрос к обработчику, проверяет данные, выполняет бизнес-логику и обращается к хранилищу.
7. Сервер возвращает статус, заголовки и тело ответа. Браузер обрабатывает ответ и отображает данные.

DNS не передаёт HTML, TLS не определяет бизнес-правила, HTTP задаёт формат запроса/ответа, а приложение решает, что делать с запросом.

## Теория 2. CORS

Same-Origin Policy ограничивает, как документ или скрипт одного origin может читать данные другого origin. Origin определяется схемой, хостом и портом. CORS — механизм, с помощью которого сервер сообщает браузеру, какие cross-origin запросы разрешены для чтения JavaScript-кодом.

Для некоторых запросов браузер сначала отправляет preflight OPTIONS, чтобы проверить разрешённые методы и заголовки. Если ответ не содержит подходящих CORS-заголовков, браузер блокирует доступ скрипта к ответу. Запрос иногда мог дойти до сервера, а серверная логика могла выполниться — это не то же самое, что ошибка backend.

CORS не заменяет аутентификацию, авторизацию или CSRF-защиту. Это прежде всего браузерная политика доступа к cross-origin ответам.

## Практика. HTTP POST с JSON

```http
POST /api/students HTTP/1.1
Host: api.example.com
Content-Type: application/json
Accept: application/json

{"isu_id":42,"group":"M3301"}
```

- POST — отправка данных для создания ресурса.
- Content-Type сообщает формат тела.
- Accept указывает ожидаемый формат ответа.
- Пустая строка отделяет заголовки от тела.
- Content-Length можно опустить по условию; в реальном запросе транспортная реализация должна корректно обозначить длину/передачу тела.

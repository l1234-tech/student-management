## Теория 1. Валидация во Flask, DRF и FastAPI

Flask предоставляет базовые средства HTTP и маршрутизации; схема валидации и сериализации часто выбирается отдельно разработчиком. Django REST Framework использует Serializer для проверки входных данных, преобразования типов и формирования представления ответа. FastAPI опирается на аннотации типов и Pydantic-модели, строит валидационные ошибки и OpenAPI-схему.

Поэтому одинаково неверные данные могут привести к разным форматам ошибок и статусам: это зависит от framework, настроек и того, как разработчик обрабатывает исключения. В нашей лабораторной №2 используется Django + DRF, и именно его serializers и ответы следует считать источником фактического поведения проекта.

## Теория 2. Жизненный цикл POST во Flask

Типичный путь: HTTP-сервер принимает запрос → WSGI передаёт его Flask → router ищет маршрут по методу и пути → Flask вызывает view-функцию → приложение читает и валидирует данные → service выполняет бизнес-правила → repository/storage сохраняет запись → view формирует ответ → Flask отправляет статус, заголовки и JSON.

Ошибки могут появиться при поиске маршрута (404/405), разборе и валидации данных (обычно 400/422 — в зависимости от API), выполнении бизнес-логики (например 409 при конфликте) или из-за неожиданного исключения (500). Конкретные статусы должны быть согласованы контрактом API.

## Практика. Потокобезопасный счётчик

```python
import threading

counter = 0
lock = threading.Lock()

def increment_many():
    global counter
    for _ in range(1000):
        with lock:
            counter += 1

threads = [
    threading.Thread(target=increment_many),
    threading.Thread(target=increment_many)
]
for thread in threads:
    thread.start()
for thread in threads:
    thread.join()

print(counter)  # 2000
```

Lock защищает составную операцию чтения и записи, поэтому инкременты не теряются. Блокировку берём на каждое увеличение; после join оба потока завершены, поэтому итоговое значение можно безопасно печатать. GIL не заменяет явную синхронизацию составных операций.

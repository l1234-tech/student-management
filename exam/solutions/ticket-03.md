# Решение билета №3

## 1. HTML и валидация
Атрибуты required, type, min, max, minlength, maxlength и pattern дают браузеру возможность проверять базовые ограничения. JavaScript нужен для межполевых и предметных правил, динамических сообщений и сложных сценариев. Клиентские проверки обходятся, поэтому сервер повторно проверяет типы, диапазоны, обязательность и бизнес-ограничения.

## 2. ORM и JPA
ORM сопоставляет объекты программы с реляционными таблицами. JPA — спецификация/API для объектно-реляционного отображения в Java. EclipseLink — реализация этого API, ORM-провайдер. PostgreSQL — реляционная СУБД.

## 3. Практика: REST
| Действие | Метод и URL | Типичный статус |
|---|---|---|
| Список | GET /api/students | 200 OK |
| Один студент | GET /api/students/{isu} | 200; 404 если отсутствует |
| Создание | POST /api/students | 201 Created |
| Частичное изменение | PATCH /api/students/{isu} | 200 или 204 по контракту |
| Удаление | DELETE /api/students/{isu} | 204 No Content |
| Невалидный ввод | Соответствующий маршрут | 400 или 422 согласно контракту |

API должно последовательно документировать статусы и формат ответов. Это распространённый вариант проектирования, а не единственная возможная политика.

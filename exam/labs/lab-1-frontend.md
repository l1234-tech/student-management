# Лабораторная №1 — Frontend без фреймворков

Источник: предоставленное ТЗ «Лабораторная 1.pdf». Реализация и пояснения: [описание лабораторных 1–2](../../docs/labs-1-2.md).

## Цель и требования
Создать интерфейс системы управления студентами без frontend-фреймворков, используя CSS и вынося бизнес-логику в отдельные файлы.

Обязательные страницы: таблица студентов с CRUD и просмотром досье; форма с ФИО, группой, ИСУ ID, общежитием, комнатой, сроком заселения, признаком иностранного студента и заметками; подробное досье студента.

Требуются адаптивность, обновление интерфейса в ответ на действия, сочетание HTML-валидации и JS-валидации, хранение в localStorage/cookies/IndexedDB согласно варианту и favicon-котик.

## Что важно понимать
- HTML описывает структуру, CSS — оформление, JavaScript — поведение.
- DOM — объектное представление документа.
- Событие (click, submit) запускает обработчик.
- Клиентская валидация улучшает удобство, но не заменяет серверную.
- JSON.stringify сериализует значение в строку, JSON.parse разбирает JSON-строку.
- Cookies отправляются браузером согласно их правилам; localStorage не отправляется автоматически с каждым HTTP-запросом; IndexedDB хранит структурированные данные асинхронно.
- CRUD означает Create, Read, Update, Delete.

## Учебный пример
~~~js
const students = JSON.parse(localStorage.getItem("students") ?? "[]");
students.push({ id: crypto.randomUUID(), fullName: "Иванов Иван" });
localStorage.setItem("students", JSON.stringify(students));
~~~

Пример иллюстрирует принцип хранения, а не утверждает, что именно этот код использован в твоём варианте.

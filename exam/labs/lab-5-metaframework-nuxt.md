# Лабораторная №5 — Frontend на метафреймворке (Nuxt)

Источник: ТЗ «Лабораторная работа №5. Frontend на метафреймворке».

## Выбор технологии

Для Vue из лабораторной №4 в ТЗ указан Nuxt. Альтернативы: React — Next.js; Svelte — SvelteKit; Angular — AnalogJS.

## Что требуется сохранить из лабораторной №4

- JWT-регистрация и авторизация.
- Список студентов.
- Поиск, фильтрация, сортировка и пагинация.
- Создание, редактирование и удаление.
- Разграничение доступа по ролям.
- Профиль пользователя.

## Возможности метафреймворка

- Серверный рендеринг (SSR).
- Динамические маршруты, включая `/students/[id]`.
- Защита маршрутов и перенаправление гостей через middleware.
- Состояния загрузки, ошибок и страница 404.
- Кеширование данных с обновлением после изменений.

## Архитектурные ограничения

Frontend взаимодействует с Java-backend из лабораторной №3. Бизнес-логика, авторизация и работа с базой данных остаются на Java-backend. Серверные возможности Nuxt применяются только для frontend-функциональности: SSR, маршрутизации, middleware и получения данных. Приложение должно оставаться адаптивным и быть контейнеризировано с Docker.

## Важные нюансы реализации

SSR выполняется на сервере, поэтому нельзя читать `window`, `document`, `localStorage` или `sessionStorage` в коде, который исполняется при серверном рендеринге. Если SSR-запрос зависит от пользователя, механизм передачи сессии должен быть доступен серверу безопасно. Токены и секреты нельзя помещать в публичную конфигурацию или HTML.

После создания/редактирования/удаления студента нужно обновлять или инвалидировать кеш списка и карточки. Backend остаётся источником истины.

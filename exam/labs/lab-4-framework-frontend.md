# Лабораторная №4 — Frontend на JavaScript-фреймворке

Источник: ТЗ «Лабораторная 4.pdf». Конкретный фреймворк пока неизвестен, поэтому ниже — общие требования.

## Требования
Перенести frontend лабораторной №1 на React, Vue, Angular или Svelte, сохранить функциональность и добавить авторизацию, роли, состояние и реактивное программирование. Использовать REST API лабораторной №3.

Нужны просмотр/CRUD студентов, поиск, фильтрация по полям, сортировка, пагинация, обновление без перезагрузки, страницы /login, /register, /profile, JWT access/refresh, выход, данные текущего пользователя, компонентная архитектура, локальное/глобальное состояние и клиентская маршрутизация.

RxJS обязателен для всех вариантов: нужно практическое применение Observable, подписок и операторов. Нужны клиентская валидация, обработка ошибок backend, индикация загрузки, защита от повторной отправки формы, Dockerfile с multi-stage build, Nginx или аналог, docker-compose.yml, .env.example и README.

## Сравнение фреймворков
- React: компоненты и hooks; глобальное состояние может использовать Context, Redux Toolkit или Zustand.
- Vue: компоненты и реактивность; Pinia — вариант глобального состояния.
- Angular: компонентная платформа; возможны Signals или NgRx.
- Svelte: компиляторный подход; stores/runes зависят от версии и варианта.

Это разные API, не смешивай их в одном решении. При этом ТЗ отдельно требует RxJS во всех вариантах.

## Ключевые понятия
Observable представляет поток значений; Subscription управляет подпиской. Для поиска часто используют debounce и переключение на актуальный запрос, например switchMap, чтобы устаревший результат не заменил новый. Клиентская защита маршрута улучшает UX, но права обязательно проверяет backend. Docker image — шаблон, container — запущенный экземпляр, Compose описывает совместный запуск сервисов.

## Практика
1. Спроектируй список студентов со состояниями loading/error/empty.
2. Опиши поток поиска с отменой устаревшего запроса.
3. Объясни защиту маршрутов и backend-проверку роли.
4. Опиши Compose для frontend, backend и БД.

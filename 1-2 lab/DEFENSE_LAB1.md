# Конспект к защите лабораторной №1 — Frontend

> **Проект:** система управления студентами общежития.  
> **Стек:** HTML, CSS, JavaScript без frontend-фреймворков.  
> **Цель:** интерфейс для просмотра списка студентов, создания и редактирования записей, удаления, просмотра досье и проверки ввода.

## Как рассказать о лабораторной за 1 минуту

В первой лабораторной мы реализовали клиентскую часть системы управления студентами общежития. HTML задаёт структуру, CSS — внешний вид и адаптивность, JavaScript — реакцию на действия пользователя и работу с DOM. На главной странице показывается таблица; форма используется и для добавления, и для редактирования; отдельная страница показывает досье студента. На этом этапе данные обрабатываются на стороне браузера. Для различения записей используется идентификатор, поля проверяются встроенной HTML-валидацией и дополнительными JavaScript-проверками. В лабораторной №2 мы расширяем архитектуру, добавляя серверное API и серверное хранение.

## 1. HTML: назначение, элементы и атрибуты

**HTML** (HyperText Markup Language) описывает структуру и смысл содержимого страницы. Это не язык программирования: HTML сам по себе не реализует алгоритм добавления студента.

- **Элемент** — конструкция разметки, например `<button>Удалить</button>`.
- **Тег** — запись в угловых скобках: `<button>`, `</button>`.
- **Атрибут** задаёт свойства: `id`, `class`, `type`, `required`, `min`, `max`.
- **Семантика** помогает браузеру, разработчику и вспомогательным технологиям понять роль элемента.

Типичная страница содержит `<!doctype html>`, корневой `html`, секции `head` и `body`. В `head` лежат метаданные, заголовок вкладки, подключения CSS и иконки; в `body` — отображаемое содержимое.

**Пример из проекта:** таблица студентов, кнопки действий и форма. JavaScript находит поля по `id`, например `document.getElementById("full-name")`.

```html
<input id="ISU" type="number" required>
<button type="submit">Сохранить</button>
```

**Ответ:** «HTML описывает структуру страницы. У нас он задаёт таблицу студентов, поля формы и кнопки действий. Атрибуты помогают обращаться к элементам из JavaScript и выполнять базовые проверки».

## 2. Структура HTML и DOM

**DOM (Document Object Model)** — объектное представление HTML-документа в памяти браузера. JavaScript может находить, создавать, изменять и удалять узлы.

**В проекте:** функция `renderStudents(students)` в `static/js/index.js` очищает `student-table`, создаёт `tr` и `td` для каждого студента, задаёт содержимое ячеек и добавляет строки.

```js
const row = document.createElement("tr");
const nameCell = document.createElement("td");
nameCell.textContent = student.name;
row.append(nameCell);
```

- `getElementById` находит элемент по ID.
- `querySelectorAll` находит элементы по CSS-селектору.
- `createElement` создаёт узел.
- `append` добавляет узел.
- `textContent` задаёт текст.

**Почему `textContent`, а не `innerHTML`?** ФИО рассматривается как текст, а не как HTML-код, что снижает риск внедрения разметки из пользовательского ввода.

**Ответ:** «DOM — дерево объектов, через которое JavaScript управляет страницей. Наш список отрисовывается динамически в `renderStudents`, поэтому строки можно обновить без ручного редактирования HTML-файла».

## 3. Формы и валидация

Форма собирает пользовательский ввод. Полезные атрибуты: `name`, `id`, `type`, `required`, `min`, `max`, `maxlength`. Типичные поля: `text`, `number`, `date`, `checkbox).

В проекте `student_form.js` подписывается на событие `submit`, отменяет стандартную отправку через `event.preventDefault()`, вызывает `validate()`, формирует объект студента и отправляет его. Для редактирования данные подставляет функция `fillForm(student)`.

```js
form.addEventListener("submit", function (event) {
  event.preventDefault();
  if (!validate()) return;
  // собрать объект и отправить его
});
```

Функция `validate()` в `validation.js` проверяет:
- ФИО — только буквы и пробелы, длина не больше 60 символов;
- группу — буква и 4–5 цифр;
- ИСУ — ровно 6 цифр, первая не ноль;
- номер общежития — целое число от 1 до 20;
- комнату — четырёхзначное число от 1000 до 9999;
- дату — корректная, не ранее 2016 года и не в будущем.

Клиентская валидация улучшает UX, но не защищает сервер: пользователь может отправить запрос без JavaScript. Поэтому в лабораторной №2 правила проверяются и на backend.

**Ответ:** «HTML обеспечивает базовые ограничения, а JavaScript реализует предметные проверки и показывает сообщения рядом с полями. До успешной проверки форма не отправляет данные».

## 4. CSS: правила, селекторы, каскад и приоритет

CSS задаёт цвета, размеры, отступы, рамки, расположение, адаптивность и состояния элементов.

```css
.edit-button {
  padding: 0.5rem 0.75rem;
}
```

Селекторы могут выбирать элементы по тегу (`button`), классу (`.edit-button`), идентификатору (`#student-table`), атрибуту или сочетанию условий. Каскад учитывает важность правила, специфичность и порядок деклараций. Обычно селектор ID специфичнее класса, а класс — селектора тега. Не следует злоупотреблять `!important`.

В проекте классы `.edit-button`, `.delete-button`, `.info-button` применяются CSS для оформления, а JavaScript использует их для поиска кнопок. При этом оформление и поведение — разные обязанности.

**Ответ:** «CSS отделяет вид от структуры. Селектор выбирает элементы, декларации задают внешний вид. Например, класс `input-error` визуально отмечает поле, которое не прошло валидацию».

## 5. Адаптивная вёрстка

Адаптивная вёрстка сохраняет читаемость и управляемость интерфейса на разных ширинах экрана. Используют viewport meta-тег, относительные единицы, Flexbox/Grid, медиазапросы `@media`, ограничения ширины, переносы и разумную прокрутку таблиц.

```css
@media (max-width: 700px) {
  .container { padding: 0.75rem; }
}
```

Медиазапрос применяет правила при выполнении условия. Адаптивность — не только уменьшение шрифта: кнопки и поля должны оставаться доступными.

На защите можно сузить окно браузера и показать, как выглядит таблица/форма. Конкретные CSS-приёмы следует сверять с текущим `static/css/style.css`, не приписывая проекту правила, которых там нет.

## 6. JavaScript в клиентском приложении

JavaScript — язык программирования, работающий в браузере. В нашем проекте он читает поля, реагирует на события, создаёт объект студента, строит DOM и выполняет запросы.

Основные элементы языка: `const` и `let`, типы данных, функции, условия, циклы, объекты, массивы, Promise и `async/await`.

Файлы клиентской логики:
- `static/js/index.js` — список, фильтры, отрисовка и кнопки действий;
- `static/js/student_form.js` — форма создания/редактирования;
- `static/js/student.js` — досье;
- `static/js/validation.js` — проверки формы.

**Ответ:** «JavaScript связывает страницу с действиями пользователя: получает значения, проверяет их, формирует объект, отображает строки и отправляет HTTP-запросы. Логика вынесена в отдельные файлы».

## 7. Типы данных, функции, объекты и массивы

Примитивные значения включают строки, числа и Boolean. Объект хранит пары ключ–значение, массив — упорядоченную последовательность элементов.

Пример объекта, который создаёт текущий `student_form.js`:

```js
const student = {
  name: document.getElementById("full-name").value.trim(),
  group: document.getElementById("group").value.trim(),
  ISU: Number(document.getElementById("ISU").value),
  dormitory: Number(document.getElementById("number-house").value),
  room: Number(document.getElementById("number-room").value),
  checkin_date: document.getElementById("date").value,
  is_foreign: document.getElementById("inostran").checked,
  note: document.getElementById("note").value
};
```

`.value` у большинства полей — строка, поэтому числовые значения явно преобразуются через `Number(...)`. Свойство `.checked` у checkbox возвращает Boolean.

Полезные методы массивов: `forEach` — выполнить действие для каждого; `filter` — отобрать; `map` — преобразовать; `find` — найти первый подходящий.

В ранней версии лабораторной №1 CRUD работал над клиентским массивом. В текущей объединённой версии репозитория этот frontend уже обращается к API лабораторной №2.

## 8. Событийная модель браузера

Событие — действие или изменение состояния, например `click`, `submit`, `input`, `change), `reset`. Обработчик — функция, вызванная при событии.

```js
filterForm.addEventListener("submit", function (event) {
  event.preventDefault();
  loadStudents(getFilters());
});
```

В обработчике фильтра мы:
1. принимаем объект события;
2. отменяем стандартную отправку формы;
3. собираем непустые фильтры;
4. загружаем подходящий список.

В проекте `addEventListener` применяется для фильтра, сброса фильтров и кнопок добавления, удаления, редактирования и просмотра досье.

## 9. Манипуляции с DOM

DOM API позволяет искать элемент, менять текст и классы, создавать и добавлять узлы. В `renderStudents` создаются строки таблицы. Кнопкам задаётся `data-id), и по `button.dataset.id` обработчик получает ИСУ конкретного студента.

В `validation.js` при ошибке добавляется класс `input-error` и создаётся `span.field-error` с пояснением. `clearErrors()` удаляет старые сообщения перед очередной проверкой.

Строить пользовательские строки через `textContent` безопаснее, чем вставлять их через `innerHTML` как HTML-разметку.

## 10. Клиентское хранение: cookies, localStorage, IndexedDB

- **Cookies** — небольшие пары «ключ–значение», которые в зависимости от настроек могут автоматически отправляться серверу вместе с HTTP-запросами.
- **localStorage** — простое синхронное хранилище строк по ключу; данные обычно переживают закрытие браузера.
- **IndexedDB** — асинхронная объектная база браузера для более сложных и объёмных данных.

В первоначальном варианте лабораторной №1 список хранился в cookies. Cookies хранят строки, поэтому структуру сериализуют в JSON и при чтении разбирают обратно. Клиентское хранилище зависит от браузера/устройства и не является общей серверной базой. Во второй лабораторной данные переехали в серверный JSON-файл.

**Ответ:** «Cookies, localStorage и IndexedDB — разные механизмы хранения в браузере. В исходной первой лабораторной использовались cookies. Они ограничены по размеру и могут отправляться с запросами; localStorage не отправляется автоматически; IndexedDB предназначена для более сложных данных».

## 11. JSON, сериализация и десериализация

JSON — текстовый формат обмена данными, поддерживающий объекты, массивы, строки, числа, Boolean и `null`.

- Сериализация — превращение программной структуры в JSON.
- Десериализация — преобразование JSON в структуру программы.
- Валидация — проверка соответствия данных правилам; это отдельный этап.

В frontend:
`JSON.stringify(student)` превращает объект JS в строку, а `response.json()` разбирает JSON-ответ API в JS-объект.

Пример структуры студента:

```json
{
  "ISU": 123456,
  "name": "Иванов Иван Иванович",
  "group": "M3301",
  "dormitory": 8,
  "room": 1201,
  "checkin_date": "2024-09-01",
  "is_foreign": false,
  "note": "Без замечаний"
}
```

JSON — не база данных и не язык программирования. В JSON нельзя записать функции, комментарии или значение `undefined`.

## 12. CRUD

CRUD означает Create, Read, Update, Delete — создание, чтение, изменение и удаление.

| Действие | В проекте |
| --- | --- |
| Список | `index.js → loadStudents()`, GET списка |
| Досье | `student.js`, GET одной записи |
| Создание | `student_form.js`, POST |
| Редактирование | GET для заполнения формы, затем PATCH |
| Удаление | `index.js → deleteStudent()`, DELETE |

ИСУ подходит как идентификатор, потому что ФИО и группа не уникальны. В актуальном репозитории frontend уже вызывает серверное API; при рассказе об эволюции проекта поясните, что в первоначальном варианте первой лабораторной CRUD был клиентским.

## 13. Организация клиентского приложения

Разбиение по файлам уменьшает смешение обязанностей. В проекте список, форма, досье и валидация находятся в отдельных JS-файлах; HTML задаёт структуру, CSS — оформление.

Это клиентская организация по задачам, не то же самое, что backend-слои. `validation.js` не рисует список, а `index.js` не должен содержать все стили и шаблоны.

**Ответ:** «Если надо поменять правило проверки ФИО, я иду в `validation.js`; если алгоритм создания строки таблицы — в `index.js`; если оформление — в CSS».

## 14. Разделение интерфейса и бизнес-логики

Интерфейс отображает данные и принимает действия; бизнес-логика задаёт правила работы системы. В лабораторной №1, поскольку backend отсутствовал, основные изменения выполнялись в браузере. Во второй лабораторной данные и проверки переехали на сервер, а frontend стал отправлять запросы и отображать ответы.

**Важное уточнение:** не называйте первую лабораторную полноценным stateless-клиентом. Stateless-взаимодействие с серверным источником данных — свойство архитектуры второй лабораторной.

## 15. DevTools и отладка

DevTools открывается клавишей F12:
- **Elements** — HTML и применённые стили;
- **Console** — сообщения и ошибки JavaScript;
- **Network** — URL, HTTP-метод, статус, request/response и JSON;
- **Sources** — исходный код и точки останова;
- **Application/Storage** — cookies и другое клиентское хранилище.

В текущей версии проекта при ошибке сохранения следует открыть Network и проверить POST/PATCH-запрос на `/api/requests`. Наличие ошибки в Console и неверного статуса в Network помогает отделить проблему frontend от отказа backend.

## Частые уточняющие вопросы

**Почему ФИО не годится как ID?** Оно может совпадать у разных студентов или измениться; API использует ИСУ как идентификатор.

**Зачем `preventDefault()`?** Отменить стандартную отправку формы/перезагрузку и запустить собственную обработку.

**Почему `Number(input.value)`?** Значение поля обычно строковое, а ИСУ, общежитие и комната нужны в объекте как числа.

**Почему `textContent` безопаснее `innerHTML`?** Текст не интерпретируется как HTML-код.

**Почему проверки нужны и на клиенте, и на сервере?** Клиентские правила удобны для пользователя, но обходятся; backend должен сам гарантировать корректность данных.

**Чем cookies отличаются от localStorage?** Cookies могут автоматически отправляться в HTTP-запросах и имеют настройки безопасности; localStorage не отправляется автоматически.

**Что изменилось в лабораторной №2?** Сервер стал источником данных, появились REST API, серверная валидация и централизованная обработка ошибок.
